# Design

## Context

See proposal.md for the accepted stance. Current collection (`collect_snapshot`, `git_evidence`, `resolve_under`) rejects ignored, credential-like, linked, non-text and large evidence. `required_subjects` treats all context/guidance as mandatory. `invoke` restricts the reviewer to a temporary packet, while `main` reserves originals and rewrites completed verdicts when they change.

Local `claude.exe --help` confirms support for `--add-dir`, normal configured tools/permissions, JSON output/schema, explicit model/effort and session persistence. This was a help inspection, not a model call. The pending invocation/diagnostic changes and completed `tighten-orchestration-handoffs` work must be preserved.

## Goals / Non-Goals

**Goals:** selected evidence is included by default; Claude can investigate relevant dependencies; required review coverage stays honest; ordinary review does not freeze other work.

**Non-Goals:** grant filesystem rights the parent does not have, bypass managed/OS permissions, authorize application edits/deployment, change model/billing routes, introduce a second strict/trusted mode, or replace the user's diagnostics/process lifecycle implementation.

## Decisions

1. **Repository investigation plus captured change evidence.** Run Claude with the repository as working directory. Retain the existing packet for selected versions/diffs and supply its absolute location using `--add-dir`. Add optional manifest `read_roots` for additional directories already authorized by the parent. Explicit external files can be copied individually into the packet; selecting one file does not require granting its whole directory. The prompt distinguishes captured change evidence from dependencies consulted in the live workspace. A larger packet alone would retain the same omission problem; a full repository copy would duplicate unnecessary data.

2. **Parent selection determines inclusion.** Remove filename, credential-pattern and Git-ignore vetoes from collection and Git evidence. Resolve explicitly selected symlinks/junctions and record original/resolved identities. Accept absolute references with deterministic packet paths for external files; collect Git history only for repository files. Preserve readable originals and selected non-text artifacts; unsupported formats are reported honestly during review rather than silently filtered. Existing parent-declared exclusions remain. Do not replace the removed vetoes with a confirmation flag or another automatic scanner.

3. **Required core and optional context.** Keep `selected_paths` and `requirements` required. Add optional `required_context_paths`, a subset of `context_paths`, for context that genuinely controls acceptance. Ordinary `context_paths` and guidance are available/applied without demanding a coverage item for every file. Existing requirement mappings remain supported and their declared evidence must be available. Missing required evidence still blocks preparation; unavailable optional context produces a visible limitation. Existing manifests use the new optional-context default without needing an opt-in flag.

4. **Normal CLI configuration.** Remove `--safe-mode`, `--restricted`, forced empty/strict MCP configuration, overlapping tool whitelists/blacklists, forced prompt denial and `--no-session-persistence`. Keep the review task advisory in its prompt and use the user's ordinary CLI permission/configuration behavior. Do not add permission-bypass flags. Preflight validates only capabilities actually used by the invocation plus the retained model/effort/subscription contract. Session continuation remains explicit; preserve independent initial-review judgment and do not automatically replay a prior session.

5. **Size controls describe resources.** Convert current 1 MB/file-diff and 8 MB aggregate input thresholds to warnings. Add optional `--max-file-bytes` and `--max-packet-bytes` limits, disabled by default, for deliberate operator budgets. Stream large copies/diff artifacts instead of eager unbounded loading. Keep output/report parsing limits separate from source inclusion; do not rewrite the user's diagnostic capture policy.

6. **Revision attribution replaces full-run reservations.** New reviews create no input reservation and require no writer quiescence while the model runs. Capture hashes/baseline and record later changed paths separately from the immutable review result. Preserve the completed verdict for its reviewed version; the parent reconciles relevant subsequent changes before applying findings. Retain legacy `--check-writes` behavior for existing callers/old reservations during migration, but stop assigning it as a prerequisite for new snapshot reviews. Never sweep another review's records.

## Concrete contracts from plan review

- The launcher retains an advisory assignment, not a technical guarantee that normally configured tools cannot write. Source changes are unattributed; remove the old docstring claim that the checkout can never change. Permission denials are reported as limitations and do not discard otherwise valid structured output; missing required coverage still yields incomplete. Explicit nested delegation remains outside this review assignment and a reported spawned-subagent execution is not accepted as an ordinary advisory review. Persisted session history is a normal configured side effect; adding launcher resume support is outside this change and no resume argument is sent by default.
- Preflight runs authentication discovery from the same repository working directory as invocation and checks actual provider/credential overrides in user, repository `.claude/settings.json` and `.claude/settings.local.json` sources. This preserves the accepted subscription/billing choice without restoring input-content filtering or disabling ordinary settings.
- `read_roots` is a unique list of absolute existing directory paths; malformed, missing or non-directory entries are structural errors. `required_context_paths` must be a unique subset of `context_paths`. Explicitly supplied role guidance must actually be available, although no per-guidance coverage entry is required; remove filename, Markdown-extension and input-size vetoes from guidance too. Excluded mapped/required context is a contradictory manifest. Parent exclusions remove paths/directory prefixes from capture, required coverage and the reviewed change; the prompt describes them as out of scope for findings, not as filesystem access controls.
- External files with identical basenames get deterministic unique packet paths under `_clanker_packet/sources/external/`; namespace-conflicting repository files get separate mapped paths. Metadata records every original subject, resolved source and snapshot path. The completed attempt retains its captured packet, and `source_evidence.read_scope` records `{repository, packet, additional_roots}`. A selected external file grants its packet copy, not access to its entire source directory.
- An optional model result `consulted_paths` lists live context inspected; the report identifies this as reviewer-attested, unhashed evidence outside freshness verification. Do not invent hashes or complete live-workspace coverage.
- New host reports have `schema_version: 2`. Valid model completion remains `execution_status: completed` and launcher exit 0 even when originals changed. After the result is finalized, comparison has its own exception boundary. `source_changes` is `{status: current|changed|unavailable, attribution: unattributed, entries: [{path, status: changed|removed|unavailable, kind: required|optional|guidance|manifest|git, reason}]}`. Original/resolved identities handle linked and external inputs; deletion, directory replacement and failed Git comparison cannot erase the captured verdict. Optional context is not required coverage, and changed-input metadata is not proof of a writer's identity.
- `--check-current` retains `current`, `eligible_for_parent_review` and its 0/3 exit convention for old and new reports and never rewrites a report. For new reports, execution status stays the recorded host status and comparison details are separate; eligibility is a conservative unchanged-and-clean shortcut. When changed or unavailable, the parent reconciles relevant paths rather than interpreting the historical review as failed. Legacy unversioned reports keep their query display behavior.
- Selected-and-excluded paths are intentionally removed from capture/core coverage; exclusions are not filesystem denies. Mapped or expressly required-context exclusions remain structural contradictions. Optional-context/guidance-only drift still sets the conservative freshness query to current=false/exit3, but never changes completeness or the captured verdict. Reported nested delegation yields host failed/incomplete with a process diagnostic and launcher exit2; existing debug captures are retained. No new command/task delegation is authorized by the advisory assignment.
- Parent already saved the starting workspace under `.clanker/relax-context-2026-10-09T093842-0700-01/baseline/` and ran the nine existing diagnostics tests successfully. Implementation/test owners compare their changes to that starting state; diagnostics/process handling is not reauthored. Focused tests add binary/non-UTF-8 originals, optional permission denial, actual guidance availability, external basename collisions, exclusions, and source-comparison failure states.

## Risks / Trade-offs

- Live dependency reads can observe a newer version than the selected snapshot → record captured-versus-live evidence and changed paths; do not claim the historical verdict certifies unreviewed changes.
- Old tests/specs assume exclusion and full context coverage → replace those expectations with trusted inclusion and required/optional cases, retaining required-evidence failures and original path identity.
- Relaxation overlaps the user's invocation work → take a starting diff, patch invocation/collection policy separately from diagnostics and owned-process handling, and verify those independent changes remain intact.
- Larger inputs consume resources → use streamed artifacts, warnings and explicit optional budgets; no default security veto.

## Migration Plan

Implement in the existing launcher and two guidance files; no new framework or dependencies. Preserve current manifest fields, preparation/report paths, model/effort behavior, diagnostics and captured findings. Update installer expectations only where they assert old policy; no installer architecture change is needed.

This change supersedes the mandatory-context/export/reservation portions of `tighten-orchestration-handoffs`. Preserve its fixture checks, producer completion and evidence handbacks. When specs are eventually synchronized, apply that completed change first and this relaxation second; do not let the earlier delta restore the strict rules. Planning does not sync/archive either change. Rollback should revert only this change's policy hunks, leaving concurrent diagnostics work intact.

Retained earlier clauses: static requirement tracing to guards/bindings/test contracts; actual before/after evidence for preservation; genuinely required unread subjects stay incomplete; native path identity/original subjects; fixture readiness, artifact producer completion and evidence handbacks. Superseded clauses: blanket filtering/export vetoes, mandatory coverage for all context, whole-run source reservations and automatic historical-verdict invalidation. The Native guidance path identity delta here targets the requirement introduced by the completed tightening change and is applied after it. Legacy record cleanup remains with the original coordinator after verifying the owned process stopped; upgrade does not sweep records.
