## Context

The completed `orchestration-routing-editor` change supplies the Python local service, shared routing resolver, React editor and optional source Node launcher. See proposal.md for motivation. Codex CLI0.118.0 was queried with initialize/initialized/model/list only and reported six older models than this session exposes, proving that local CLI catalog and native dispatcher capabilities must remain separate.

## Goals / Non-Goals

**Goals:** metadata-only local discovery, truthful refresh/cache states and full provider-scoped selectors; preserve Python-only installed runtime and unchanged routing semantics.

**Non-Goals:** run inference to test entitlement, call public model APIs with API keys, change authentication/settings, install/upgrade CLIs, auto-generate Adaptive maps, or replace native dispatcher capability evidence.

## Decisions

1. Use a Python standard-library discovery helper beside the existing scripts. Invoke fixed protocols through argument arrays from an isolated temporary working directory. Resolve native executables (including Codex npm vendor executable on Windows); optional CLANKER_CODEX/CLANKER_CLAUDE executable overrides remain server-environment-only. Unknown wrappers/protocols fail explicitly rather than use shell parsing.
2. Codex uses stdio app-server initialize/initialized/model/list, paginating within bounded limits. Claude uses its verified initialization model-info control protocol; no user message is ever sent. CLI customizations/tools/MCP are disabled for Claude. Return whitelisted metadata only; do not read authentication files or return raw process logs. Claude Code 2.1.278 was verified with control_request initialize and matching control_response.response.response.models; the official matching SDK returns this initialization models array. Preserve ModelInfo.value, displayName and supportedEffortLevels. Missing efforts remain unknown. Require the installed help to advertise bare/safe/restricted/strict-MCP/stream-json/no-session-persistence/permission controls before probing; fail closed without weaker retry. Use bare mode, empty tools/MCP/settings, denied permission prompts, and remove provider credential environment variables. This reports advertised metadata, not account entitlement.
3. Keep per-provider in-memory cache and last-success timestamps. The first authenticated GET /api/models performs discovery independently of /api/config; later GETs serve cached results for five minutes. POST /api/models/refresh with exactly an empty object forces refresh. Concurrent calls share the active refresh rather than launch duplicate processes. Each provider probe is deadline/output/model-count bounded; errors preserve stale last-success data. No disk cache or preferences schema change.
4. API shape: {providers:{codex:ProviderCatalog,claude:ProviderCatalog}}. ProviderCatalog contains status (live/cached/stale/unavailable), source, cli_version (nullable), updated_at (nullable ISO UTC), error (nullable sanitized string), and models. A model contains id, label, provider, efforts (string array or null for unknown), default_effort (string or null). Return IDs exactly as reported, including aliases, without inventing canonical equivalents.
5. Offer CLI-reported entries by provider+ID through native selects for routes, temporary sessions, and choosing a model for an Adaptive profile. Remove manual model-ID entry and static bundled alternatives. Retain the current own-or-inherited model when absent from discovery as a labeled disabled option; never rewrite the draft on refresh. Stale last-success catalogs remain usable. Empty, loading, failed, or 404 catalogs without retained results offer no new models and explain how to refresh. Existing profile editing/reset and missing-profile validation remain unchanged. Label the preview section "Preview model and reasoning".
6. Package the helper in both installers and update fixture tests. Native source review plus focused subprocess/cache/HTTP/component tests and rendered picker verification establish acceptance. Retain prior routing and launcher regression behavior.

## Risks / Trade-offs

- CLI protocol/version variation -> verified adapters, bounded parsing and provider-specific unavailable state; no inference fallback.
- CLI catalogs may be stale or differ from session tools -> provenance labels and unchanged exact native gates.
- Discovery may consult provider metadata using existing login -> no prompt/model turn and no credentials are exposed by the editor.
- In-memory cache is lost at server restart -> intentional simplicity; retain current selections and explain that new choices require CLI metadata.
- Aliases may resolve differently later -> display reported IDs honestly and do not rewrite saved choices.

## Migration Plan

Build the updated editor and run the existing installer when desired; no saved preference migration. Roll back helper/UI together and preserve preference files. Node remains optional outside source development.

## Detailed compatibility and lifecycle contracts

- A provider probe has a 30-second total deadline including help/version/handshake; maximum combined output is 1 MiB, maximum NDJSON line 256 KiB, maximum 20 Codex pages and 1,000 model rows. Repeated pagination cursors, malformed metadata or exceeded bounds fail the provider. Text metadata is bounded and control characters rejected. Source is exactly `codex-cli` or `claude-cli`.
- GET after the five-minute TTL synchronously re-probes, sharing any already active refresh. Cache time tracks attempts to avoid repeated automatic failures; updated_at tracks only last success. Forced refresh retries immediately. Models are deep-copied for callers. A fresh success is live, reuse is cached, failed refresh with earlier models is stale, and no successful result is unavailable.
- Each probe owns a POSIX session/process group or a Windows kill-on-close job assigned before execution. The discovery manager tracks active probes, rejects new work after close, and cancels owned processes on EditorServer.server_close. Timeout, output overflow, normal completion and shutdown all close process trees and reader resources. Windows child windows remain hidden. Do not mutate process-wide environment for per-probe isolation.
- The separate discovered-model type permits efforts:null. For known metadata, selectable efforts are the intersection of CLI-reported values and bundle effort_orders, in policy order. For unknown metadata use the policy order with an explicit unverified note. Reported values outside policy are annotated as unavailable for new selection. Existing selected values stay visible/selectable with an annotation; neither model changes nor catalog refresh silently rewrites effort. Discovery takes precedence over static per-model suggestions, but never modifies the bundle or resolver.
- Claude model values are exact selection tokens; label known aliases (default, opus, sonnet, haiku, including context suffixes) as aliases whose resolution may change. Do not normalize or rewrite them. Selecting an alias still requires its own Adaptive profile or Fixed mode; the launcher remains authoritative.
- The endpoints are additive. No API/schema version bump is needed: a new UI receiving 404 from an old server explicitly reports discovery unavailable and retains current selections but offers no new model choices. An old UI against the new server remains compatible but lacks discovery controls; rebuild/reinstall is required to obtain the new UI. Cover the 404 fallback in component tests.
- Codex uses its existing login and may perform ordinary CLI-managed cache/log or token-refresh writes. Discovery code never reads credentials or edits settings. This is not a guarantee of zero CLI-managed filesystem writes. Claude bare discovery does not verify account entitlement. Do not snapshot or return authentication contents for verification.

## Adapter and UI handoff details

- Codex requests model/list with includeHidden:false and limit:100. Map model -> id, displayName -> label, supportedReasoningEfforts[].reasoningEffort -> efforts, and defaultReasoningEffort -> default_effort. Pagination uses nextCursor verbatim with repetition and count guards. Hidden entries are not requested. No default-model selection is applied.
- Both catalog endpoints return HTTP200 and the identical providers object even if every probe fails. The manager converts probe exceptions (including timeout) to fixed sanitized provider errors. Once closed, catalog calls raise a dedicated closed error translated to HTTP503 with a discovery-specific message, never a configuration-file error. Probe both providers concurrently; a request is bounded by the 30-second probe budget plus at most five seconds of cleanup.
- Reuse the existing launcher Windows containment mechanism: suspended Popen, ctypes job assignment, thread enumeration then ResumeThread, with hidden windows. Any extension to its process helper must preserve review defaults and receive focused regression coverage. POSIX uses a new session. Tests exercise a real owned grandchild on timeout/shutdown where the host supports it; unexercised platforms remain explicit limitations.
- Support Claude native executables on Windows and executable CLI files on POSIX; Windows npm .cmd/.ps1 wrappers are explicitly unsupported. CLANKER_CLAUDE and CLANKER_CODEX reference absolute executable files only, not argument strings. Codex's known npm vendor executable is resolved without executing a wrapper; on Windows x64 check the current vendor/<target>/bin/codex.exe layout first, then the legacy vendor/<target>/codex/codex.exe layout. Missing/unsupported install forms produce a fixed explanatory error and retain current selections.
- Manual model entry is removed from route/session selectors and the AdvancedProfiles creation form. Profile creation uses only the selected provider's discovered catalog. Existing profiles remain editable/resettable, including profiles for models no longer reported. Do not automatically create profiles or change reasoning modes.
