# Proposal

## Why

Post-update CardForge and MediaRanker logs show avoidable fixture repair, review-context gaps, and verification against unfinished artifacts. Existing coordination rules need clearer handoff evidence, and Windows guidance paths can falsely fail local packet readiness.

## What Changes

- Make fixture/API checks and producer completion explicit integration prerequisites, with an owner when workers cannot execute checks.
- Require prompt handback of inaccessible advisory evidence and reconciliation of changed paths against cooperative write checks.
- Trace static review requirements to relevant implementation, guards, bindings and fixtures; verify preservation claims against an actual before/after baseline and retain required-context coverage.
- Clarify readable transition records and separate task completion from review/runtime evidence coverage.
- Match captured guidance using native path identity while retaining original manifest coverage subjects and existing exclusions.
- Add isolated regression coverage for guidance aliases, mappings and unavailable evidence.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `development-orchestration`: explicit integration prerequisites, blocked-worker handbacks, and checked write-path reconciliation.
- `claude-cross-review`: static evidence sufficiency and portable guidance identity during preparation.
- `orchestration-run-log`: readable transitions and separate completion/evidence states.

## Impact

Changes are confined to orchestration/specialist instructions, the existing local readiness comparison, focused Python tests, and this change's artifacts. No dependencies, model defaults, manifest schema, reviewer invocation, diagnostic/progress logging, authentication, billing, installers, or CardForge/MediaRanker sources change. The user's concurrent Claude invocation/diagnostics work is preserved. Implementation is authorized; installation, publication and archival are outside this task.
